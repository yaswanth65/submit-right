💳 Payments API

Payment processing and webhook handling via Razorpay

POST /api/payments/webhook

POST /api/payments/webhook 🔗 Webhook

Razorpay payment webhook handler

Webhook endpoint that receives payment status updates from Razorpay. Called by Razorpay servers on payment events.

⚠️ Note: This is a webhook endpoint. It does not require standard bearer token authentication. Instead, it validates the webhook signature from Razorpay header.
📥 Request Headers
Header Type Description
x-razorpay-signature string HMAC SHA256 signature for verification
📥 Request Body

Webhook payload from Razorpay containing payment event details:

{ "event": "payment.captured", "payload": { "payment": { "entity": { "id": "pay_123456", "entity": "payment", "amount": 15000, "currency": "INR", "status": "captured", "method": "card", "order_id": "order_123456" } } } }
📤 Response (200 OK)
{ "event": "payment.captured", "documentId": "doc-123", "status": "paid", "updated_at": "2026-04-02T15:00:00Z" }

Supported Events

  • payment.captured - Payment successfully captured
  • payment.failed - Payment failed (optional handling)

Processing Flow

  1. Razorpay sends webhook with x-razorpay-signature header
  2. API verifies signature using Razorpay webhook secret
  3. If valid: Update payment transaction status in database
  4. If valid: Update document status to "completed"
  5. If valid: Send confirmation notification to client
  6. Return 200 OK to acknowledge receipt

Error Codes

401
Invalid webhook signature - rejected
500
Server error processing payment

Implementation Notes

  • Webhook signature validation is mandatory for security
  • Implementation must handle duplicate webhook deliveries
  • Empty/null responses are acceptable for webhook
  • Razorpay retries webhook on non-2xx responses
  • Store webhook payloads for audit trails

Payment Processing Flow

1. Client Initiates Payment

Client calls POST /api/client/payments/create-order to create a Razorpay order.

Request: { "documentId": "doc-123" } Response: { "id": "order_123456", "amount": 15000, "currency": "INR" }

2. Frontend Integration

Frontend receives order details and opens Razorpay checkout popup:

// Frontend JavaScript const options = { key: "razorpay_key_id", order_id: "order_123456", amount: 15000, currency: "INR", handler: (response) => { // Handle payment success } }; const razorpay = new Razorpay(options); razorpay.open();

3. Payment Processing

User completes payment in Razorpay checkout modal.

4. Webhook Notification

Razorpay sends payment.captured webhook to POST /api/payments/webhook

5. Database Update

API updates payment transaction and document status:

  • Payment status: pending → paid
  • Document status: payment_needed → completed
  • Audit log entry created
  • Client notification sent

6. Confirmation

Client receives confirmation and document becomes available for download.

Razorpay Integration Details

Configuration

  • Gateway: Razorpay (Indian payment service)
  • Currency: INR (Indian Rupees)
  • Amount Format: Paise (100 paise = 1 rupee)
  • Minimum Amount: 100 paise (₹1.00)
  • Authentication: API Key + Secret Key

Supported Payment Methods

  • Credit/Debit Cards (all networks)
  • Net Banking (all major banks)
  • UPI (Google Pay, WhatsApp Pay, etc.)
  • Wallets (PayZapp, Mobikwik, etc.)
  • EMI options

Key Concepts

  • Order: Represents a payment request with amount and metadata
  • Payment: Actual transaction after customer pays
  • Webhook Signature: HMAC-SHA256 hash for security verification
  • Webhook Secret: Private key for signature validation

Testing Payment Webhook

Development Environment

For testing webhooks locally, use Razorpay's Test Webhook feature:

  1. Log in to Razorpay Dashboard
  2. Navigate to Settings → Webhooks
  3. Click "Test Webhook" button
  4. Select event type (payment.captured)
  5. Send test payload

Test Payment Methods

Razorpay provides test card numbers:

  • Success: 4111 1111 1111 1111
  • Decline: 4000 0000 0000 0002
  • Any CVV/Date (in test mode)
